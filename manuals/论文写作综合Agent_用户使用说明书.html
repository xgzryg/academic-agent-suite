02

安装与检查

把一个完整文件夹放入宿主实际使用的 skills 目录。内部功能不需要逐个安装。

1

解压并检查层级

安装包文件名为 paper-writing-agent-v1.1.3.zip。解压后找到 paper-writing-agent 文件夹，主 SKILL.md 应在该文件夹第一层。

正确的安装结构
目标 skills 目录/
└─ paper-writing-agent/
   ├─ SKILL.md
   ├─ INSTALL.md
   ├─ skills/
   ├─ references/
   └─ scripts/

避免多套一层同名目录，或只复制 SKILL.md 而漏掉内部文件。

2

放入当前宿主的目录

先确认当前应用或账户实际读取哪个 skills 目录，再放入整个文件夹。Windows 上可能是 D:\Codex\.codex\skills 或其他配置位置，不要只凭示例猜路径。

若已有同名安装，先确认旧版身份并做好备份，再按宿主方式处理旧安装、腾出目标位置后放入新版。不要把新版嵌套在旧版里面。

安装脚本拒绝覆盖同名目标；本说明书不会替你修改任何安装或配置。

如何下达任务

不必背功能名。说明“做什么、依据什么、改到哪里、何时算完成”通常更有效。

建议说清为什么需要可以这样写
目标与范围确定只改片段，还是串联多个阶段。只润色 Discussion；不要改 Methods 和统计结果。
当前材料区分本研究事实、当前稿和学习文风的范文。manuscript.docx 是主稿；results.xlsx 是结果依据；example.pdf 仅供学习结构。
不可改内容保护数字、术语、方法与人工决定。保留 HR、95% CI、P 值、协变量、现有引用和全部不利结果。
产物与位置直接得到能继续使用的文件。输出英文 Word 和逐条修改说明，保存到 D:\论文项目\输出。
执行方式减少重复确认，同时保留必要的作者决定。按已确认大纲连续完成；缺失关键方法参数时列明，先做不受影响部分。
联网与审稿范围决定检索方式、审稿者能看到什么。允许公共文献检索；审稿只看正文和补充材料，不看作者内部笔记。

04

从结果到完整论文

这条路径适合已有真实研究结果的项目。如果还没有结果，应先做选题、研究设计或文献综述，不能直接补写不存在的实验和发现。

开始前准备这些材料

  • 研究问题、研究类型和拟解决的具体问题。
  • 已确认的方法记录：纳排、处理、分析、仪器或实验条件等。
  • 最终结果表、图表、图注信息及统计输出。
  • 已有主稿、真实参考文献和作者已做的决定。
  • 目标语言、文章类型、目标期刊（如有）及输出目录。

材料不齐也可以开始整理，但影响正文真实性的缺项必须补齐或明确标记。

定义一个实际完成标准

例如：完成主文各章节和图注，数字与结果表一致，关键外部论断有可核验引用，输出指定格式，并列出剩余作者待办。

“保证录用”“一定达到顶刊水平”或“提高到显著”不能作为可保证的完成标准。目标应对应可检查的文稿和证据。

完整交付可以包括正文、修改说明和待补信息表；没有必要的文件不强制生成。

识别材料与事实依据

确认当前主稿、最终数据/结果、图表与方法记录；辨明哪些文件只是风格参考。列出会影响写作的真实缺项。

形成论文逻辑和章节大纲

确定研究问题、核心结果顺序、图表与正文的对应关系，并给出 Methods / Results 大纲。

新起草完整 Methods / Results：大纲未确认时先确认；已有确认直接沿用。

先写方法、结果和图注

以真实研究过程和实际结果为依据。缺失参数不能补猜，图表中的符号、单位、分组和分析口径须一致。

完成前言与讨论

围绕问题、已有证据、研究增量与局限组织论证。需要补引时实际核验文献，区分关联、因果与假设。

完成标题、摘要、结论和 Highlights

根据完整正文提炼信息，确保摘要数字、主要结果与结论没有超出正文。

按需要翻译、润色或精简

优先选择当前缺少的一步。中文稿不会仅因选择期刊风格就自动变为英文；翻译和润色可以明确串联。

整稿核对与可选审改

核对正文、图表、引用和声明。若希望不同实例反复审改，应另行明确开启审稿—返修循环并给轮数。

导出和交付

保存当前可编辑稿、必要附属材料与真实待办。根据可用工具核查指定格式；投稿材料准备完成不会自动发送投稿。

05

连续执行、分批处理与恢复

自动化的关键是事先说明执行范围、已有确认和完成标准。普通可核查步骤可以连续完成，作者事实与科学取舍仍由实际信息决定。

同一任务内连续执行

把依赖链写进一条指令

例如“翻译 → 润色 → 引用/数字核对 → Word交付”。材料和授权齐全后，agent 会完成这些明确阶段；不会自动增加选刊、投稿或新分析。

已有稿件反复改进

明确开启审稿—返修循环

给定轮数、审稿可见材料、允许改动和目标。普通润色或单次审稿不会自行升级为循环。

多篇材料分批处理

每篇独立输入、独立输出

先按清单识别每篇主稿和对应附件，再逐篇处理。同一项目的信息不能串入另一篇。某篇缺材料时，记录缺项并继续独立可做部分。

长稿与跨任务续作

先核当前文件，再继续

让 agent 保存必要的已完成阶段、当前稿、受保护部分和下一步。恢复时沿用最新人工修改，检查已有结果是否仍可用，不从头无差别重做。

情况会如何处理怎样减少不必要中断
Methods / Results 新稿缺少已确认大纲时先提交大纲。提供你已经确认的具体大纲；确认过的不重问。
Proof 校样未说明模式时默认逐节确认。明确写“自动连续检查全文”。
真实参数或作者声明缺失暂停依赖部分，完成其余可做内容。提供实际伦理、方法、作者和投稿声明信息。
需要新分析或新实验列出需要什么，不写成已经完成。另行明确批准方案并提供数据或实际执行结果。
可逆文字修改已获授权按范围继续，不重复逐句确认。明确章节、可改程度、不可改字段和输出。

审稿—返修循环

先审一次，再进行最多 N 次“返修 + 再审”。审稿者和返修者必须是实际不同的子 agent，最后返修稿也必须经过审查。

先看懂轮数

3拖动查看执行上限

这是上限示意。基线审稿已满足目标时，可以 0 次返修结束；没有必要用完所有轮数。

可配置内容默认或规则自然语言示例
最大轮数明确开启但未指定时，最多 3 次返修及其再审。最多 2 轮；或者 0 轮，仅做基线审稿。
完成目标范围内实质问题有真实修正或证据回应，最终稿经复核。解决重大一致性问题，创新性表述与文献证据一致。
创新性评估默认不开启；明确要求后加入。加入 PubMed 近似文献与逐篇创新性比较。
每轮人工确认默认不逐轮等待；你可以要求开启。每轮审稿后先让我确认修改策略，再返修。
可见范围与改动范围沿用实际指定材料和作者约束。审稿只看正文/补充；只改工作副本文字，不重算统计。

创新性评估会做什么

  1. 提取稿件具体主张：问题、对象、数据、方法与发现。
  2. 进行互补的宽窄检索，结合真实相关论文查近邻。
  3. 实际阅读摘要；关键细节需要时再查可取得全文。
  4. 逐篇说明已有先例、本稿新增点及未能判断的部分。
  5. 据证据保留、收窄或修正创新表述，再交回审稿/返修。

相似分用于找到候选文献；有限检索不能证明全球首次。禁网时可以整理已有证据，但不能声称完成了实时查新。

需要作者信息缺少真实参数、决定或新的分析授权。
能力或证据阻塞关键材料、网络或真实子agent工具不可用。
用户停止按你的要求结束，保留已完成阶段和当前版本。
如果宿主没有真实子 agent 工具，agent 会说明限制，并在得到你的同意后才改成单 agent 顺序审改。两个角色口吻不能冒充两个独立实例；达到轮数上限也不能跳过最后再审。

常见问题


安装了，为什么仍然不识别调用名？
检查目标skills目录是否属于当前宿主/账户，主SKILL.md是否位于正确层级，整个文件夹是否完整。按宿主方式刷新或开新任务，再让它核对入口。必要时提供你实际安装的主SKILL.md完整路径供它读取。复制文件不会保证当前对话热加载，也不会自动给本包增加一个全局角色编号。


我要记住所有内部功能名称吗？
不需要。始终从 $paper-writing-agent 开始，描述当前任务即可。功能查询用于理解能力和选择更精确的范围；内部支持一般由主入口按需要调用，不必全部执行。


为什么要求自动写作，它还在等待我？
先看具体等待事项。未确认的新Methods/Results大纲、图形摘要文字方案、真实方法参数和作者声明可能需要你的决定；已经给出的确认会复用。如果只是Proof逐节等待，可明确切换为“自动连续核查全文”。


能否从一个选题直接全自动写出研究论文？
可以协助检索、设计研究、组织综述证据和起草已有依据的部分。没有真实研究数据和执行记录时，不能补出实验结果、统计值或伦理信息。完整原创研究论文需要对应的真实材料。


为什么设置3轮，会有4次审稿？
先有基线审稿R0，再有最多3次返修及各自再审R1、R2、R3。只有“返修+再审”完成才算一个往返；目标提前达成可以提前结束。


轮数用完，但问题仍存在怎么办？
查看最后受审稿、未解决问题及停止原因。如果你决定继续，可明确增加总轮数和允许处理的范围；如果问题需要新数据、分析或作者事实，先补足相应条件。不能仅为通过而降级问题或夸大贡献。


没有找到近似文献，是否证明创新性很强？
不能这样判断。要区分检索式过窄、数据库覆盖不足、接口失败、只读摘要与真实缺少近似研究。结论应具体限定在实际检索和阅读范围内；创新主张靠逐篇比较和本研究证据支持。


能否保证查重率、AI检测率或期刊录用？
