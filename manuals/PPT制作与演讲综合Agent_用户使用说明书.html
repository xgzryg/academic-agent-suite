01

先做出一份演示

把任务交给主入口，具体分支由 agent 根据需要读取。

安装后，在支持本地技能的 AI 宿主里输入 $ppt-production-agent，附上材料并说清场景。你无需记住 16 个内部技能名称，也无需自己把多个 agent 串起来。

可复制示例
$ppt-production-agent
根据这篇论文制作 15 分钟中文组会汇报，另留 5 分钟问答。
请完成可编辑 PPTX、逐页备注、HTML/Word 演讲稿和备答。
突出研究问题、关键图表、证据与局限；成果保存到我指定的项目目录。
一开始最好给出的信息

材料与当前稿、受众与场景、主报告和问答时长、语言、模板、必讲内容、修改范围、成果目录。已有信息会继续沿用，普通配色和排版可直接采用合理默认值。

本包是 AI 宿主中的 agent/skill 文件夹。材料理解和写作由模型完成，脚本执行生成、同步与导出；模型、Python、Office、字体和网络服务由当前环境提供。

02

安装与首次调用

完整文件夹即一个安装单元；先核对宿主实际使用的 skills 目录。

  1. 解压

    解压后保留完整的 ppt-production-agent 文件夹。内部直接包含 SKILL.md、skills/、scripts/ 与 engines/。

  2. 放入实际 skills 父目录

    整体复制到宿主配置的技能目录。目标结构应为 <skills 父目录>/ppt-production-agent/SKILL.md。不要只复制入口文件，也不要拆散子分支。

  3. 检查现有运行环境

    让宿主检查 Python、所需库及可用渲染器。先复用已安装环境；安装脚本不自动下载依赖，也不改变全局配置。

  4. 刷新并调用

    按宿主方式刷新技能或重启对话，输入完整 slug。没有自动发现功能但可读取本地文件的宿主，可直接读取本包 SKILL.md 后执行。

可复制示例
python scripts/install.py --destination "/path/to/your/skills" --dry-run
python scripts/install.py --destination "/path/to/your/skills"

在解压后的包根目录执行上述命令，并替换示例路径。--destination 是父目录，脚本自动添加包名称；--dry-run 只显示计划位置。遇到同名已安装文件夹时会拒绝覆盖。

Windows PowerShell 也可使用：

可复制示例
$SkillsParent = 'D:\YourTools\skills'
python .\scripts\install.py --destination $SkillsParent --dry-run
python .\scripts\install.py --destination $SkillsParent
安装完成的判断

宿主能读取主入口和包内分支，能发现实际可用工具，并能按要求生成文件。它不会自动加入你自定义的编号菜单，也不会注册桌面应用、后台服务或第三方账户。

从材料自动完成整套制作

明确允许连续执行，让 agent 完成必要制作与核查。

可复制示例
$ppt-production-agent
请根据我提供的材料自动完成一套可用于现场讲述的演示。

场景：中文组会汇报；听众有本领域基础。
时间：主报告 15 分钟，另留 5 分钟问答。
输入：本次附件中的当前论文、真实图表和我的结果说明。
模板：使用我指定的模板；若未提供，采用清楚可投影的中性设计。
范围：可调整结构与版式，保留原始事实、数据、单位和结论强度。
输出目录：使用我指定的项目目录，原始文件保留。
交付：可编辑 PPTX、逐页演讲者备注、HTML 与 Word 演讲稿、提示卡、备答；有可用渲染器时另交 PDF。

依次完成材料读取、证据对应、故事板、页面与口语稿、生成和同步、最终实际页面核查。
输入充分时连续执行，不为常规排版重复询问。
关键事实或必讲材料缺失时说明具体影响，继续不依赖缺项的部分。
不要把旧模板中的身份、图表或数据当作我的内容。
最后交付实际文件，并说明未完成的导出、核验或素材缺项。

你会得到什么

交付物用途
可编辑 PPTX继续修改和现场放映；讲者备注跟随各页。
HTML 演讲稿浏览器离线分页阅读、提示卡、全文模式与本地练习计时。

05

演讲稿、提示卡与排练

屏幕只放必要信息，备注负责把图表和故事讲清楚。

可以只写开场、某几页备注、完整逐字稿或双语演讲稿，也可以从当前 PPTX 导出已有备注。模型负责撰写内容；导出脚本不会凭空补写缺失的稿子。

层次主要作用
屏幕文案标题、关键证据和必要解释，方便听众阅读。
逐页口语稿 / notes完整可说出的句子、图表解释和自然转场。
提示卡 / cues强调、停顿、指图和时间提醒，便于脱稿。
问答与备用页台下问题的依据、短答和补充材料。
可复制示例
$ppt-production-agent
只根据我指定的当前 PPTX 写英文演讲稿，目标 8 分钟。
保留数字、术语和结论强度，语言适合口头汇报。
逐页写入备注，给简短提示卡，导出 HTML 与 Word；不要重新制作可见页面。

HTML 讲稿怎样使用

在浏览器打开生成的 speaker_notes.html。可选择分页稿、提示卡或全文模式，通过上一页/下一页、跳页框和键盘左右键切换；使用页面中的开始、暂停和重置按钮计时。打印时可用全文稿。

计时只在打开的浏览器页面内工作，不控制 PowerPoint、不录音、不生成声音，也不在关闭页面后继续运行。需要实际试讲反馈时，向 agent 提供录音文字或各段实测时间。

时间如何理解

默认估时按中文 230 字/分钟、英文 130 词/分钟，每个有正文页面另加 5 秒停顿。可按个人习惯修改。故事板中明确写入的逐页计划时间会用于计划累计，并另外给出文字估计。数字、公式、演示、互动与问答可能使实际用时不同。

可复制示例
$ppt-production-agent
我实际试讲用了 18 分钟，需要压到 12 分钟。
请保留关键结果和结论，压缩重复解释，把非必需技术细节移入备用页。
同步修改 PPT、备注和 HTML/Word 稿，列出被压缩的内容；不要只提高估计语速。
06

可选审查—修改循环

明确轮数和完成目标；每一轮都围绕当前实际稿件。

普通制作会做必要自检。希望经过独立视角反复审查时，可以明确开启循环。宿主支持真实委派的情况下，由审查子 agent 提问题，修订子 agent 修改工作稿，主 agent 协调版本与最终交付。

可复制示例
$ppt-production-agent
在当前这套 PPT 和材料范围内开启审查—修改循环，最多 3 轮。
请使用一个真实子 agent 审查，另一个真实子 agent 负责修订；主 agent 负责版本协调和最终交付。
完成目标：关键主张有对应证据；必须展示的结果均保留；最终实际渲染没有妨碍阅读的遮挡/溢出；页序、备注和讲稿一致；按我设定的语速估计主报告不超过 15 分钟。
允许修改当前工作稿的结构、表达和版式；不改原始数据、研究结论或人工固定图。
每轮审查最新稿，修订后更新 PPT、备注、HTML/Word 演讲稿和受影响的预览。
达到目标、达到轮数上限、我要求停止或遇到必须补充的材料时结束，并分别说明停止原因。
无需逐轮确认常规修改。若宿主不能创建真实子 agent，请准确说明，由单 agent 做一次检查，不伪称独立多人评审。
设置项怎样填写
最大轮数例如最多 3 轮；不是保证必须做满。
完成目标用实际可判断的条件描述，例如关键证据完整、实际页无遮挡、讲稿同步、时间符合计划。
允许修改范围结构、表达、版式、当前工作稿；明确固定数据、结论与人工图。
逐轮确认希望看过再改时写明；允许连续修改时说明不需确认常规改动。
停止条件达到目标、到轮数上限、用户停止或必需材料缺失。
对循环结果的正确理解

达到轮数上限不等于已经达标。报告应区分已解决和未解决问题，说明实际停止原因。没有真实子 agent 能力时，单个 agent 的多视角检查不能称为多人独立评审。

若需要创新性或相关研究对照，可加一句：“在已授权联网范围内检索 PubMed 近似文献，逐项比较研究问题、对象、方法与发现，说明阅读范围；不要把检索相似度当创新评分。”PubMed 结果只是候选证据，最终判断需要阅读内容。

07

已有 PPT、模板和图片怎么处理

始终指定当前稿，说明要保留的人工内容和允许改变的范围。

局部修改

可复制示例
$ppt-production-agent
请以我指定的 current.pptx 为当前稿，先读取实际页面和备注。
只修改第 4 页的标题措辞与第 7 页表格中我指定的数值，其他内容和页序保持。
保留原始文件，结果写入项目工作稿；不要从旧故事板重建整套 PPT。
同步这两页的备注和讲稿，检查混合字色、换行、图表及页码是否受影响。
不能可靠编辑的复杂对象先说明实际限制。

套用模板

提供实际模板和新内容。agent 先读取页型和槽位，再选页、复用与填充，清除旧研究、姓名、日期和占位内容。要制作通用模板时，需要划分固定装饰与内容区域，并用另一份不同内容验证复用。

包内 assets/templates/neutral-academic.pptx 提供四页原创中性学术模板。方括号标明需要替换的位置，正式演示中必须填入真实内容；可以直接编辑 PPTX，或修改相应 JSON 后生成。

图片或截图重建

提供清晰图片，说明复现内容还是借鉴版式。可重建真实可读的文字和结构；照片、医学影像和缺原始数值的复杂数据图可以继续作为图片。仅有截图不能恢复不存在的精确原始数据。

对象 / 路线可以怎样编辑需要了解的范围
原生文字、形状、表格作为 PowerPoint 对象修改文字增长仍可能改变换行，需要看实际页面。
原生数据图表修改对应数据及可用图表样式模板中的图表以其实际类型和系列结构为界。
SVG → DrawingML修改转换后的文本、形状或路径矢量图通常不是带数据工作表的原生图表。
照片、扫描图、实验图片缩放、移动、按允许范围裁切图片内部文字/数据不会自动成为可编辑对象。
模板整段替换保留几何、段落属性与各段首 run 样式新文字的局部强调需要重新设定或精确 run 修改。
SmartArt、OLE、媒体与复杂动画尽量保留当前文件已有对象保留不等于已支持其内部语义编辑或跨平台播放。

只补 notes 时可以保留可见页面。出现人工改稿与旧故事板冲突时，先读取实际成品更新工作稿，再同步讲稿，不能从旧 JSON 重建覆盖你的修改。

08

命令行与可复用工作稿

普通用户可以直接用自然语言；下面用于手工运行和工程衔接。

以包根目录为工作目录，或将脚本路径替换为 $SKILL_ROOT 指向的实际包根。work 请使用项目内的任务目录或其绝对路径。成果应写到项目中。

从故事板生成可编辑 PPTX

可复制示例
python scripts/native_deck.py /path/to/project/work/storyboard.json --output /path/to/project/work/presentation.pptx

原生页型：封面、章节、目录、内容、双栏、表格、图表、时间线、图片、引语、总结和结束页。主题：academic、business、teaching、dark、minimal。图片路径相对故事板文件解析。包内 assets/examples/native-demo.json 是明确标注的合成示例。

同步核对与演讲稿导出

可复制示例
python scripts/speaker_pack.py /path/to/project/work/storyboard.json --pptx /path/to/project/work/presentation.pptx --check-only
python scripts/speaker_pack.py /path/to/project/work/storyboard.json --pptx /path/to/project/work/presentation.pptx --out-dir /path/to/project/work/speech --docx
python scripts/speaker_pack.py /path/to/project/work/current.pptx --out-dir /path/to/project/work/current-speech --zh-cpm 220 --en-wpm 125

--pptx 同步检查用于 JSON 输入，核对页数、ID、顺序、标题和实际备注。它不单独证明图表或科学结论正确。PPTX 输入沿当前页序提取已有备注，缺失保留为缺项。

高级 SVG 与模板路线

可复制示例
python engines/easyslides/engine.py svg /path/to/project/work --output /path/to/project/work/deck.pptx
python engines/easyslides/engine.py template-inspect /path/to/project/work/template.pptx --output /path/to/project/work/library.json
python engines/easyslides/engine.py template-plan /path/to/project/work/library.json --slides 1,3,3,5 --output /path/to/project/work/fill_plan.json
# 按真实内容编辑 fill_plan.json 后再执行填充
python engines/easyslides/engine.py template-fill /path/to/project/work/fill_plan.json --output /path/to/project/work/filled.pptx

SVG 页面放在项目的 svg_output/，逐页备注放在 notes/ 的同名 Markdown。模板填充不自动执行 notes 或转场计划；已有稿补备注使用 notes-init 和 notes-apply，具体步骤见包内 references/engine-usage.md。

用实际 PowerPoint 渲染

可复制示例
powershell -NoProfile -File scripts/render_pptx.ps1 -InputPptx "D:\MyProject\work\presentation.pptx" -OutputDir "D:\MyProject\work\rendered" -Format both

需要 Windows 与已安装的 Microsoft PowerPoint。使用新的输出目录；脚本只关闭本任务打开的文稿。其他系统需使用实际可用的渲染器。没有渲染条件时，如实说明最终视觉检查尚未完成。

输出工具默认保护已有同名成果，明确获准更新的目标才使用相应 --overwrite 或 PowerShell 的 -Overwrite。完整参数用脚本 --help 查看；安装脚本没有覆盖开关。

需求环境条件可以先做什么
内容理解与写作可读本地文件的 AI 宿主与模型只在确实读取后声明材料覆盖范围。
PPTX 生成与编辑Python、python-pptx、Pillow先复用现成环境，按报错补齐实际缺少的库。
模板图表工作簿openpyxl缺库时保留未更新状态，不能称旧数据已替换。

实际 PPTX PNG/PDFPowerPoint + PowerShell，或其他可用渲染器无渲染器时明确未完成视觉核查。
离线 HTML现代浏览器直接打开文件，无需服务器或额外前端依赖。
PubMed / 现行资料核验网络及当前可用检索工具无网时整理现有材料与待检索主题。
真实子 agent 循环宿主委派能力 + 明确开启不具备时准确说明单 agent 工作范围。

本地生成基本 PPTX 和离线讲稿不需要外部内容平台；AI 模型本身是否离线取决于宿主。包不内置模型、Office、字体、账户、付费图像/语音服务或后台调度器。

10

常见问题与交付判断

用实际成果和准确范围判断任务是否完成。

找不到 $ppt-production-agent？

核对宿主实际读取的 skills 父目录，以及是否多套了一层同名目录。完整结构应让 SKILL.md 直接处于 ppt-production-agent 内。按宿主刷新方式重载，或在支持本地文件的环境中明确读取入口。

需要再安装其他开发者的 agent 吗？

运行所需的包内分支与选定引擎通过相对路径提供，无需寻找开发机原有 agent。公共库、模型及 Office 等外部运行条件仍需当前环境具备。

能一键把任何图片变成全可编辑 PPT 吗？

能够基于实际图片重建可辨认的文字和结构。照片、复杂纹理和缺少原始数据的图表仍可能保留图片；不能把整页截图包装成完全可编辑成果。

从 PPT 导出演讲稿，为什么有空缺？

文件本身可能没有 notes。导出工具会报告缺少原始备注；若希望补写，应请求 agent 根据当前页面和材料撰写，再写入备注并导出。

我手动修改了 PPT，怎样继续？

明确指定当前 PPTX，说明人工固定项和要改范围。agent 应先读取当前页序、内容和 notes，更新对应工作稿与讲稿，不从旧故事板覆盖。

生成完成后可以说页面已检查吗？

只有实际查看过最终 PPTX 的渲染，才可说明实际视觉核查范围。XML、对象边界、文字密度或 SVG 预览检查各有用途，都不能独自替代 PowerPoint 最终显示检查。

估计时间准确吗？

它是计划辅助。语速、数学表达、复杂图表、演示与互动会影响真实时长。用自己的试讲计时反馈再压缩内容，比单纯提高估计语速更可靠。

为什么循环到第 3 轮还会有问题？

最大轮数是停止边界，不是保证达标。应分别交代已解决、未解决问题和停止原因。缺失关键材料时需要真实补充，不能用反复改写掩盖。

会自动上传、发送或定时运行吗？

制作与导出不自动授权发布、发送、付费或后台调度。需要这些操作时另行明确任务与范围，并使用宿主实际支持的能力。

怎样判断这次交付够用了？

看实际要求是否完成：正确的当前版本、应有内容、真实数据与来源、可读页面、匹配的备注和讲稿、所需格式，以及明确列出的尚未完成事项。已经满足目标时即可交付，不为凑问题继续循环。
