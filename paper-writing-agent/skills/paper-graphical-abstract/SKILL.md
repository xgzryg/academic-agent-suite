# 论文摘要图

先读取 [共享规则](../../references/shared-rules.md)。本文件是综合助手的内部功能分支，读取它不切换主角色。用户当前任务和已确认设计优先；本分支的科学准确性、证据边界和必要方案确认不得被工具建议替代。

## 何时使用与分流

- 用户希望创建、修改或审阅 Graphical Abstract、视觉摘要或论文主要发现的概念图时使用。
- 对真实数值的散点图、生存曲线、统计图，先用 [科研图表与导出](../paper-research-artifacts/SKILL.md) 根据数据绘制，再纳入本分支的版面；不能用图像生成模型代画精确数据点。
- 用户要求编辑已有图像时读取当前图片并沿用已授权修改范围；不要从旧描述重建并覆盖人工固定成品。
- PDF 输入按需使用 [PDF](../paper-pdf/SKILL.md)，Word 输入按需使用 [文档](../paper-documents/SKILL.md)。从已读取材料传递信息，不让用户重复提供。

## 最小输入与事实表

检查现有上下文中的标题、摘要、主要发现或 Highlights、目标期刊/尺寸要求以及已有图或设计。没有 Highlights 时可从 Results 的主要结果及小标题提取。只补问会改变研究含义或出图决策的缺失信息；非关键配色可给明确默认。

在内部或可审阅规划中列出：

| 字段 | 内容 |
|---|---|
| 研究对象与设计 | 人群、模型、样本与观察/实验设计；不从领域名推测 |
| 核心新发现 | 1–3 个最值得呈现的发现，各自对应原稿位置 |
| 证据性质 | 观察关联、干预证据、机制支持或假设 |
| 必须保留内容 | 数值、单位、方向、重要限制、用户固定项 |
| 视觉用途 | 期刊摘要图、报告预览或其他明确用途 |
| 输出约束 | 比例、像素或物理尺寸、分辨率、格式、字体、是否需要可编辑标签 |

范文只能借鉴组织与风格，不能成为当前研究事实。证据不足时简化或标识未知，不编造机制、细胞类型、效应方向或实验结果。

## 文字规划：必须可直接据此出图

先给简明完整的文字方案，包含下列实际设计内容，而非只有“简洁、美观”等形容词：

1. **核心信息。** 用一句话概括视觉摘要要传达的发现，不把论文全文塞入图中。
2. **阅读顺序与区域。** 说明从左到右或从上到下的路径、各区内容和相对占比。区域数量取决于研究，可按研究对象、方法、发现、意义组织，不强制套四栏。
3. **视觉元素。** 写清每个对象采用什么示意符号、图形或已有数据图；元素位置和来源可追溯。
4. **英文标签。** 将每条待印刷的文字先写为 `<English label>`，逐条对应对象/发现；尖括号是规划分隔符，默认不印到图上。使用关键词或短句，保证拼写、大小写、缩略语和单位准确。
5. **连接和科学含义。** 列出每条箭头/线段连接谁、代表过程还是关联；只有证据支持时用因果方向。假设不得画成已经证实的机制。
6. **配色。** 指明主色、强调色和同类元素的对应；避免高饱和度、仅靠红绿区分或色觉缺陷者难分辨的组合，必要时同时用形状或线型区分。
7. **版面和留白。** 图像为主、文字为辅；标签不叠图，元素不挤边；不加入杂乱装饰。默认不在画面上重复论文标题，期刊或用户有明确要求时采用其要求。
8. **画幅和交付。** 列出准确比例、像素/物理尺寸、目标分辨率与格式，并说明标签是否需要可编辑叠加。

### 画幅与字号核算

- 比例按宽÷高计算：1200×800 是 **3:2**；1280×720 是 **16:9**；1080×1080 是 **1:1**。不能沿用来源把 1200×800 写成16:9的错误。
- 期刊给出物理尺寸时，像素 = 英寸 × dpi；毫米先除以25.4。例如160 mm宽、300 dpi约为1890 px；高度再按指定比例计算并按工具能力合理取整。
- 300 dpi 是来源建议，改变 dpi 标签不会自动增加细节。真实输出的像素、比例及物理尺寸须一致。
- 无衬线字体和8 pt是来源起点，不是所有尺寸的固定答案。字号按最终展示尺寸核对；8 pt在300 dpi对应约33 px，只是渲染换算，不代表任何字体都同样清楚。
- 若生成工具只支持某些尺寸，先采用可用画幅，必要时用合适版面导出；不得把裁切、缩放或附加空白伪称为原生尺寸生成。

## 方案确认与连续执行

**新方案先交付文字规划，询问是否采用/修改并等待明确答复，然后生成最终图像。** 这保留来源的设计确认步骤。

以下情况沿用已有授权，不重复确认：

- 用户已经给出明确版面、标签与内容并直接要求生成。
- 当前会话已有认可方案，用户让继续出图或只作明确局部修订。

用户尚未确认时可以准备标签和生成提示，不能把等待误当图像生成已经获准。源文“最多一轮改方案”“一张图一个对话”只是经验，不限制用户反馈次数。

## 生成、检查和修正

1. 根据确认方案和事实表构建生成提示，列出所有文字、元素、关系、画幅及不可增补内容。
2. 按宿主可用工具生成或编辑；操作已有图片时先读取实际图像。工具能力和执行规则受宿主约束，不依赖其他安装目录中的 skill。
3. **查看实际成图**，核对核心发现、对象数量、标签逐字拼写、方向/箭头、数值单位、颜色可辨性、留白、边界和整体阅读顺序。只核对有证据和实际可见的内容。
4. 修复真实发现的错误。文字不可靠时可在图像中留出标签空间，使用可编辑文本叠加；不要声称图像模型一定能正确写字。需要图表/排版导出时调用包内科研图表分支。
5. 根据用户反馈在已确认范围内调整。交付前查看最终文件；未经用户许可不覆盖已有人工固定图。
6. 如果当前环境没有图像生成或编辑能力，交付完整文字方案、标签清单和可执行生成提示，明确“尚未生成最终图像”，不能把文字提示当成图像完成品。

## 输出

- 确认前：核心信息、逐区布局、英文标签、证据/连接说明、配色和尺寸、需用户决定的实际选项。
- 确认后：最终图像与完整路径；实际格式/尺寸；必要时可编辑标签或图表源文件；只列真实未解决问题。
- 默认PNG；用户或期刊接受时可用JPG。可编辑稿、矢量稿或其他格式按需要交付，不作无用多版本。
- 文本布局与图像最终结果有差异时如实说明，不能保证“所有文字正确”或“必定符合期刊”。

## 完成标准

真实文件已生成且已查看；科学元素和标签与当前稿一致；关系不超证据；标签可读并无已知错字；比例与声称的规格相符；无主要内容被裁切。若仅完成设计方案则按方案阶段交付，不宣布最终出图完成。
