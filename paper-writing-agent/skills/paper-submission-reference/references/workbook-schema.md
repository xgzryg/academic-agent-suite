# 工作簿结构与脚本接口

## 交付文件

- `论文投稿信息总表.xlsx`：唯一结构化主表，可由作者或 agent 继续修改。
- `论文投稿信息参照文档.docx`：从当前 Excel 生成，不作为反向更新来源。

## 工作表

`使用说明与状态`、`稿件信息`、`作者信息`、`作者单位`、`贡献与确认`、`声明`、`伦理与注册`、`数据代码材料`、`编辑与审稿人`、`上传文件清单`、`缺项与待确认`。

字段型工作表使用统一列：字段 ID、中文字段、English field、值、状态、来源、可见性、备注、最后确认日期、关键项、适用性。作者、单位、贡献、审稿人与文件清单使用便于批量维护的宽表，并保留记录状态、来源、可见性、备注和确认日期。

脚本另维护隐藏技术表 `字段元数据`，逐字段保存工作表、对象 ID、字段名、当前值、状态、来源、可见性、备注和确认日期。每次 `validate` 或 `render` 都从当前可见工作表同步更新；它用于保证宽表中的每个字段仍有独立元数据记录，不是第二资料源，也不应手工编辑。

不要改名或删除工作表和标题行。可以增加数据行；脚本按标题名读取，不依赖固定列号。

## 临时预填 JSON

`init --seed-json` 接受 UTF-8 JSON。它只是把已抽取信息写入 Excel 的临时载体，交付后不保留为第二资料源。

```json
{
  "fields": {
    "manuscript_title": {
      "value": "Example title",
      "status": "抽取待确认",
      "source": "标题页",
      "visibility": "论文公开",
      "note": "第1页"
    }
  },
  "authors": [
    {
      "作者ID": "A01",
      "作者顺序": 1,
      "投稿显示名": "Lin Chen",
      "邮箱": "lin@example.org",
      "单位ID": "AFF01",
      "通讯作者": "是",
      "记录状态": "抽取待确认",
      "来源": "标题页"
    }
  ],
  "affiliations": [],
  "contributions": [],
  "reviewers": [],
  "files": []
}
```

`fields` 可使用四个字段型工作表中的任意字段 ID。重复实体的键应使用对应 Excel 标题；未知键会被忽略并在命令输出中报告。

## 命令契约

```text
init --output PATH [--seed-json PATH] [--force]
validate --workbook PATH
render --workbook PATH --output PATH [--force]
```

- `init` 默认拒绝覆盖已有文件；`--force` 仅在调用者已明确授权覆盖该目标时使用。
- `validate` 更新“缺项与待确认”和“使用说明与状态”，保存当前工作簿，并把 JSON 摘要打印到标准输出。
- `render` 先执行相同验证，再生成 Word；Word 文件默认拒绝覆盖。
- 返回码 0 表示命令成功执行，不表示投稿资料已经完整；最终状态以输出摘要中的 `document_status` 和 `blocking_count` 为准。

## 适用性

条件字段由控制字段激活，例如 `human_research_applicable=是`。控制字段未知时，控制字段本身仍阻塞最终版；条件字段在控制项确认前不重复制造缺项。作者明确确认控制项为否或不适用后，条件字段不阻塞，但保留原值供审计，不自动删除。
