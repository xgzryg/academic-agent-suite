# Data and code availability support

Adapted from the local data-availability router and its workflow, repository,
statement-pattern and FAIR references. Use this before
[paper-research-artifacts](../../paper-research-artifacts/SKILL.md) when preparing
a data/code statement, repository plan, source-data index or metadata document.
Creating local materials does not authorize uploading, licensing or publishing.

Inventory the datasets underlying the actual manuscript and SI: generated raw
data, processed data, figure source data, reused datasets, software outputs and
models. Map each to its real location, owner, version and permitted access.
Classify routes as public repository, controlled access, within paper/SI,
reused public source, third-party restricted, justified request, embargoed, or
not applicable. Do not mark an empirical study as having no datasets.

Use a mandated repository when the current journal/data-type rule requires it;
otherwise consider a suitable discipline, institutional or general repository.
Check actual service availability and policy before recommending a specific
deposit. A planned repository is not an existing record. Never invent a DOI,
accession, reviewer link, committee, release date, licence or approval.

For a data record, identify title, creator, year, repository, identifier and
version where applicable; cite reused datasets that support conclusions.
Use a persistent record rather than an expiring sharing link as the primary
identifier. Reviewer access and public release can occur at different stages.
State lawful/ethical restrictions, eligibility, responsible access body and
request route; do not force protected participant or licensed third-party data
into a public deposit.

FAIR support means checking findability, explicit access conditions, useful
community file formats and vocabulary, and documented reuse conditions. Include
the meaningful README elements: files and their purpose, variable definitions,
units/missing codes, provenance/processing, relevant software, version, permitted
access/licence and citation. Map source data to actual panels/tables. Reuse a
project index; do not add checksums, a new manifest or a frozen schema without
a concrete need that changes a downstream operation.

Draft patterns are conditional, with placeholders for unknowns:

- Public data: “The [data type] supporting [scope] are available from [actual repository] under [assigned identifier].”
- Mixed data: distinguish newly generated data, reused public data and figure source data with their separate locations.
- Restricted data: state the real reason, owner/access body, procedure and conditions; “available on request” alone does not explain access.
- Embargo: state the assigned record, actual review access and supported release date/event only when permitted and known.
- In-paper/SI-only: use this claim only when the supporting data really are present in the named files.
- No data: use only when no datasets were generated or analysed, not for an unavailable empirical dataset.

Return ready-to-paste text in the requested language plus material missing
fields and repository actions. Apply the named journal's current, stage-specific
requirements; do not treat every unknown administrative field as a reason to
stop all authorized writing or accuse the author of noncompliance.
