# 实际子 agent 工具适配

宿主提供什么工具就用什么工具，先检查当前目录和 schema。以下是调用示意，不是命令执行凭证。

## 当前 Codex collaboration 类接口

审稿者使用 `spawn_agent`：任务名包含轮次；`fork_turns="none"` 时给足当前主稿、可见附件、目标及包内技能的绝对路径。模型和 reasoning 默认不传，继承当前设置。把返回的真实 task name / agent ID 保存到本轮记录。

不同 `spawn_agent` 启动返修者。默认每轮使用新返修者；如果继续同一返修者更节省上下文且没有污染风险，可 `followup_task`，但必须与审稿实例不同。调用开始后等待实际完成，必要时用 `send_message` 纠正范围；不要把已发出任务当完成。等待遵循宿主时间上限并保持必要进度更新。

下一次验收使用新审稿上下文；若宿主槽位不足，先等前任务结束，再启动。不要把作者整段对话作为审稿上下文自动 fork。部分宿主有 `close_agent` 时可在拿到产物后释放；没有这个工具就不编造调用。

## 其他宿主

有 `Task` 或其他真实子 agent 工具时，阅读其 schema，传同等角色职责和输入范围，并保存实际返回的执行标识。不同工具名称不改变稿件真实性、阶段顺序和最后再审要求。

## 不可用时

子 agent 不可用：说明本次不能运行请求的双子 agent 工作流，保留已完成的材料/配置。询问是否接受单 agent 顺序处理；接受后明确标注替代模式，不称为独立双代理。

不要用用户侧 `create_thread` 代替内部委派，除非用户另外明确要求新建可见任务。不要为绕过能力缺失自动调用第三方付费模型、安装服务或修改宿主配置。
