# 审稿子 agent 任务模板

替换下列任务字段后，交给实际审稿子 agent。提供原始受审材料，不提供预期答案或作者希望得到的评价。

> 使用包内 `<package>/skills/aequitas/SKILL.md` 审阅 `<current-manuscript>`。本轮版本为 `<version>`，这是模拟论文评审。只读以下明确可见材料：`<visible-files>`；未列出的作者笔记、代码和数据不在评审范围内。已确定目标为 `<goal>`，作者已确认的研究事实/不可变约束为 `<constraints>`。这些约束不能阻止你报告真实错误，但未经授权不要改分析或文件。
>
> `<previous-issues-and-response-if-any>` 是前轮问题及实际修改证据，逐项回到当前稿核对；作者称已解决不等于已解决。创新性开关 `<novelty>`，网络范围 `<network-policy>`；开启时读取包内 paper-novelty-assessment 并核对实际文献证据。你没有审稿结论数量配额，也不需要为了与前轮不同而制造新问题。
>
> 输出到 `<review-output-directory>`，不改稿件。给出具体证据位置、影响和最小修正；保留旧问题 ID，新问题给新 ID。区分重大实质问题、小问题和可选风格建议。判断当前版本是否满足目标，以及剩余问题能否在已授权范围内返修。需要新数据/实验/作者决定时具体说明。最后保存机器可读的 review.json，字段参见 state-interface.md；agent_id 用调用方提供的真实执行 ID，无法在自身上下文获取时让主 agent 用工具结果补入，不自编。

若无法读取当前稿、关键证据或需要的工具，报告失败/缺失，不返回通过。只有摘要时明确阅读范围。不同虚拟审稿视角不等于真实独立实例；报告依实际执行方式命名。
