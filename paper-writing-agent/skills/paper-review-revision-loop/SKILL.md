# 审稿—返修循环

先读[共享规则](../../references/shared-rules.md)，然后执行这里的实际调度流程。本分支只在用户明确要求开启循环时使用；普通审稿、一次返修和文字润色不自动进入循环。用户开启循环授权本任务范围内的双子 agent 委派和工作副本编辑，不授权修改研究设计、额外分析、外发稿件或投稿。

## 配置与轮次

复用已经确定的当前主稿、审稿可见范围、可改内容、不可改事实、附件、作者决定、语言和网络条件。已经明确的范围不重复确认；不把代码或作者内部材料仅因被论文提及就纳入审稿。范围不明且会改变评审有效性时，依[Aequitas 可见范围](../aequitas/references/reviewer-visible-scope.md)先解决该缺项。

| 参数 | 默认与含义 |
| --- | --- |
| `max_rounds` | 未提供时 3；表示最多几次返修及其再审，可以为 0（仅基线审稿） |
| `goal` | 用户目标；缺省为实质问题已修正或有证据回应、剩余限制准确披露、返修稿经复核且没有新事实/一致性错误 |
| `novelty` | 默认 false；明确要求创新性评估或查近似文献时 true，读取[创新性分支](../paper-novelty-assessment/SKILL.md) |
| `network_allowed` | 遵循用户/宿主限制；禁网时不伪称完成现行文献创新性核查 |
| `human_checkpoint` | 默认 false；用户要求每轮批准时 true，审稿后等作者决定再返修 |
| 子 agent 模型 | 默认继承当前宿主/用户设置；只有已有明确模型选择时才传覆盖参数 |
| 输出位置 | 用户指定位置或当前项目内的本次 `review-revision/`；源稿保留，所有工作副本和状态在任务目录 |

在开工进度中说清轮数、目标、可见范围、网络及创新性设置；这不是再索取已给的确认。先做基线审稿 R0，然后最多 N 次“返修 Vn → 再审 Rn”。最多 N+1 次审稿。基线满足目标可以 0 次返修结束。**最后一次返修必须再审，不能到上限后交未经再审的新稿。**

## 实际执行

1. **准备**：核对当前材料身份，创建工作副本；按[配置与状态接口](references/state-interface.md)建立 `state.json`。初始副本、可见附件、作者约束和已选目标明确记录。状态脚本只记录轮次和文件，不创建子 agent，也不代替科学判断。
2. **基线审稿**：用宿主真实委派工具启动审稿子 agent，实际读取包内[Aequitas](../aequitas/SKILL.md)及其依赖。使用[审稿任务模板](references/reviewer-task.md)，提供当前材料与非引导性的任务简报。要求真实审阅、证据位置、问题编号、目标判断和可否继续修正。创新性启用时读取实际检索证据，不只接受作者自评。
3. **审稿判定**：主 agent 回读审稿报告和所指实际材料。只纠正可验证的事实误读，不为了通过而降级意见。将实际工具返回的 agent ID 和当前版本写入审稿记录。达到目标则停止；否则先检查是否有尚待作者信息/新分析授权的问题，以及轮数是否已到上限。
4. **返修**：用另一个真实子 agent，实际读取[Veritas](../veritas-agent/SKILL.md)，按[返修任务模板](references/reviser-task.md)修改指定的新工作副本。传原评语、证据、范围和已确认答案。每条意见回答已完成、部分完成、有依据不采纳或待补；写出实际修改位置。未做分析不得改成已做。
5. **提交本轮版本**：主 agent 检查实际产物、关键数字、引用、图表及回复的一致性。记录新版本和回应；新版本状态只能是“等待再审”。返修 agent 不得把自己的修改判为评审通过。
6. **再审**：启动一个新的审稿上下文，直接读返修稿、可见附件、前轮问题和必要回应证据。默认不继承作者对话或作者希望得到的结论。复核旧问题是否真实解决，并查本次修改引入的实际问题。它仍是模拟评审，不能宣称期刊录用或跨模型验证。
7. **继续或结束**：重复 3–6，遵守最大返修次数。每次验收完成后更新状态；最终依据最后受审版本交付。验收后若还改了文件，要标明该版本待审并在尚有授权范围时复核，不能沿用旧的通过结论。

审稿内部的多视角可以是清楚标注的虚拟审稿人集合；循环中的审稿者和返修者必须是实际不同的 agent 实例。不要为了凑视角无条件递归再开一批子 agent。若用户明确要求每个视角也独立创建，按当前宿主槽位顺序完成。

## 宿主工具与隔离

读取[工具适配说明](references/host-tools.md)。优先使用当前真实可调用的子 agent 工具；不能把自然语言“调用 Aequitas”冒充已委派。记录工具返回的真实 ID，不自编 ID。审稿和返修按依赖顺序运行，不并发写同一稿件。

如果宿主支持不继承历史的上下文，审稿使用该方式并只提供审稿材料。可见范围是一项应遵守的访问约束，不是操作系统沙箱保证；同一模型家族的不同实例也不能被称作跨家族独立验证。

缺少子 agent 能力时，如实交付准备情况，并询问是否接受单 agent 顺序审改；在得到同意前不声称双子 agent 循环已运行。不自动创建用户侧新任务、外部模型服务或定时任务。

## 问题与停止判断

- 用稳定问题编号及具体证据维护状态；新问题才给新编号，不每轮清空重写。正确内容不凑问题，真实分歧可保留。
- 实质缺陷不能只靠更婉转的措辞关闭；有证据的不采纳经审稿核对后可结案。需要新的实验、分析、伦理事实或作者决定时留下具体待办。
- 目标达成依赖当前稿实际证据。`goal_met=true` 不能同时有本轮范围内仍开放的 critical/major 问题；创新性作为目标的一部分时，证据核查未完成也不能算完成。用户要求评分时可报告，但不默认设置任意分数阈值。
- 停止状态区分 `goal_met`、`max_rounds_reached`、`needs_input`、`blocked`、`user_stopped`。轮数用完不等于质量通过；审稿失败、网络失败和未改动不是成功。
- 没有可执行修正且条件未变化时，停止并列明原因；不重复循环，不删除旧状态。人工逐轮确认启用时，等待范围仅限依赖该决定的下一次返修。

## 最终交付

交付最终实际稿件、最后审稿意见、逐条回应及简短轮次总结：最大/已完成轮数、真实停止原因、已解决问题、剩余问题、最后受审版本、创新性证据覆盖和未验证部分。按用户格式导出，Word/PDF 依相应内置工具核查；未渲染时明确版面未验收。

单次 Nature Review Studio 的 DOCX/Markdown 对应规则适用于它的报告；本循环的版本稿、检索证据及内部状态是用户明确请求的多轮工作产物，不受单次报告“两文件”限制。不得因此丢弃实际修改稿或状态。
