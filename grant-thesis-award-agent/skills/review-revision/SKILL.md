# 审读与落实修改

遵守 [共享规则](../../references/shared-rules.md)。选择对应文种的审查分支与当前模板，明确审查范围；局部润色不自动扩展到重新设计研究。

单次预审：读取实际稿件及必要证据，给出问题位置、证据、影响、可行修改，区分重要问题、一般建议和待核事实；明确正确部分。不能只凭风格偏好反复判失败。修改任务要改实际工作稿，并逐条记录已改/保留理由/待补证据，最后检查正文、图表和回复说明的一致性。

## 可选审稿—返修循环

只有用户明确说开启循环、多轮审修等才启动。复用已给参数；未给最大返修轮数可声明默认2轮，完成目标默认“已发现且能够在现有证据和授权范围内修复的重要问题已解决，未解决项如实列明”。用户设置具体目标时以其为准，但不能把“保证中标/通过答辩/获奖”当可验证目标。

最少记录：当前工作稿；max_revision_rounds；目标；本轮修改计数；未解决事项；最终复查结果。长任务写入用户已有项目记录，短任务不强建状态系统。

1. 先检查宿主是否真的提供委派工具。可用时创建一个审读子agent，传入当前稿、必要原始证据、模板、范围和评判目标；不给它期望的“通过”答案。其输出必须有位置和依据。
2. 若目标已达成，结束。否则由另一个真实子agent按审读意见修改，传入相同事实和编辑权限；修改者不能自行编造缺失数据或批准自己的稿。
3. 主agent整合实际修改文件，核对主稿指向，增加返修计数，再交审读者检查修改后的版本。**每次返修后都复查，包括最后一轮。**
4. 达到目标或已完成N轮返修后停止，因此最多N次返修、N+1次审读。卡在缺数据、缺权属证明或不可执行实验时记录原因，不靠改文字制造解决；无进展时可提前停止并交付。
5. 若用户要求逐轮确认，在可审阅结果形成后等待其决定；否则按已授权轮数连续执行。用户中止时保存当前可用结果与未完成项。

无法真实委派时说明能力限制，可以在用户允许的范围做顺序多视角审读，不能称为独立子agent循环。技能文件本身不提供调度服务或后台常驻。

最终交付：实际修改稿、审读意见、逐条处理说明、实际审读/返修次数、停止原因、未解决项。轮数用尽不是通过。若包含创新性审读，调用 [evidence-research](../evidence-research/SKILL.md) 并保留真实检索范围。
