# 标题、摘要、结论与致谢

先读取[共享规则](../../references/shared-rules.md)；学校结构、字数和标准要求参见[当前要求](../../references/current-requirements.md)。只处理用户指定部分，避免因一个摘要请求重写整篇论文。

## 输入

使用当前论文正文、已核准的结果表、已确认题目和学校要求。补充用户已有术语表、语言偏好、需要突出的贡献与真实致谢信息。完整正文尚未具备时，可依据明确的结果集拟工作稿，同时标明尚未能进行全篇一致性检查；不能补出缺失研究内容。

## 执行

1. **确定事实基础。** 提取研究对象、目的、设计、主要方法、样本量、关键结果、结论强度和限制。优先使用用户指定当前稿与实际结果，核对正文与表图冲突。不要从旧摘要或范文恢复已被修改的数字和方法。
2. **标题与关键词。** 标题围绕核心问题、对象和必要方法形成准确、可读的候选项；数量按用户需要，避免塞入所有结果。学校或用户明确长度优先，无统一的字数硬阈值。未证明的因果、机制和“首次”不写进标题；关键词使用能代表实际研究的规范术语，避免只增加热门词。
3. **中文摘要。** 按学校要求采用结构式或非结构式，覆盖实际目的、方法、主要结果和结论。结果优先突出回答问题的发现，必要时保留关键数值和不确定性；不凭摘要长度补充新结果。若确为开题摘要，明确是计划研究，不伪装为完成论文摘要。
4. **英文摘要。** 基于核准内容形成自然、符合学科表达的英文，不机械逐词直译。随后逐项对照目的、对象、物种、样本量、数字单位、方向、方法、时态和结论强度。中文改动影响事实时同步英文；英文表达优化也不能升级科学结论。
5. **结论与贡献。** 从真实结果综合回答研究问题，不重复完整结果清单，不新增验证或机制。创新比较需要外部证据时使用[证据检索](../evidence-research/SKILL.md)。将观察发现、方法贡献、理论解释和应用可能分别说清，未查证的首创判断不写成定论。
6. **局限与展望。** 指明具体设计、测量、样本、资料和分析限制会怎样影响解释或适用范围。局限可能降低结论确定性，不能强制描述成不影响结论。未来工作与这些问题相连，清楚使用计划或建议状态，不写成既有成果。
7. **致谢。** 使用用户提供的真实姓名、机构、资助及贡献，语气按本人偏好。缺少姓名、关系、年份、资助编号或生活经历时先保留待补，不创造导师帮助、家庭故事、学习年限或致谢对象。

## 一致性核对

交付前对照标题、摘要、正文、图表、结论及展望的研究范围、术语、数量与证据强度。特别检查“一个由若干元素组成的对象”没有被改写成“若干对象”，计划数与实际数没有互换，关联没有升为因果，结论“已证实”与展望“仍需验证”没有冲突。

优先修正会改变读者理解的问题；局部语言替换不产生无意义的大量对照表。用户希望审阅改动或改动较大时，可给原文／修改／理由表，事实冲突单独说明。

## 交付与限制

交付请求的标题与关键词、双语摘要、结论、局限展望或致谢。需要落到 Word 中时通过[学术文档](../academic-documents/SKILL.md)操作当前工作副本。不得把没有全稿依据的工作稿称为最终定稿，不能承诺评审结果或用固定硕博字数替代学校要求。

本分支主要依赖文本推理和文件操作；文档读取输出、补充文献核验仅使用包内支撑与宿主真实工具，不依赖外部本机技能目录。
