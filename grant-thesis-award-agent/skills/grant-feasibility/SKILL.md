# 研究基础、条件与可行性

阅读[共享规则](../../references/shared-rules.md)和[当前要求](../../references/current-requirements.md)。本分支的核心是说明“已有何种直接支撑、哪些条件已落实、哪些仍缺证”，不以成果数量替代关联性。

## 输入

- 本项目研究问题、模块/方案、期限和当前稿。
- 作者代表作、专利、数据、预实验及可定位图表。
- 申请人的实际贡献、团队成员分工和相关经验。
- 设备、样本/队列、合作、伦理与许可、时间或预算资料中与任务有关的部分。
- 当前资助要求和机构预算口径；只写科研基础时无需追问整份预算。

文件阅读与保真编辑调用[学术文档](../academic-documents/SKILL.md)；文献身份、具体结果和相近研究核对调用[文献与证据](../evidence-research/SKILL.md)。

## 执行步骤

1. **提取真实成果。** 按原文记录成果内容、身份、年份、作者贡献、技术/资源、结果和局限。论文中未给出的影响因子、引用次数或专利状态不推算为事实；这些指标也不是本分支的默认必填项。
2. **标清完成状态。** 分开已发表、已完成未发表、预实验、在研、计划和可通过合作取得的资源。作者提供但未见证明的信息标清来源；“团队将开展”不能改写为“团队已完成”。
3. **关联研究模块。** 逐项解释成果支撑了哪个假说、测量、方法或资源环节。将多篇相关工作整合为研究脉络，明确延续和仍待突破的部分，避免机械逐篇罗列或牵强挂靠。
4. **解释预实验。** 记录研究问题、观察范围、主要发现、来源图/表、局限和可支持的结论。有限样本中的可行性观察不自动证明机制、疗效、泛化或成功概率。
5. **逐项论证条件。**
   - 理论：关键假说是否有直接研究或合理推论支撑。
   - 技术：所需方法已掌握、需优化还是尚未建立，证据是什么。
   - 人员与平台：任务由谁承担，设备/样本/合作是否真实可用。
   - 时间：资源获得、伦理流程、招募/制备、分析等耗时与项目期限是否匹配。
6. **处理真实缺口。** 对影响核心目标的不足说明会影响哪个环节、可用替代或补证方式；不能用空泛“具备完善平台”掩盖实际缺失。合理的高风险探索可有不确定性，不要求所有研究事先完成。
7. **形成工作文本。** 按研究模块组织前期基础，随后说明适用可行性和关键条件。格式、字数和栏目按当前模板；对应2026国自然情境使用作者稿修改、证据整理与论证建议，不声称整份AI稿可提交。
8. **核对一致性。** 检查正文中的“已完成”、图表数据、团队分工、专利/论文状态与原材料一致；同一资源在多个模块的投入不能相互冲突。

## 需要经费说明时

只在用户任务或目标模板要求时进入，不把海外预算分类、工资限制或间接费算法用于国内项目：

1. 读取资助方及依托单位的实际科目、计算方式、费率和可列支范围。
2. 用“科目—对应任务—数量/工作量—单价—依据—年度—金额”说明每项经费。已有金额先检查算术和任务对应。
3. 缺单价、用量、费率或计费口径时保留待补项，不使用演示默认值。
4. 需要计算时明确税费、福利、设备、分包或间接费用是否计入及其依据；无法确认口径时不要给貌似完整的总额。
5. 交付计算依据和简明说明供机构核实；不声称完成财务资格审核。

## 输出

- 按模块整合的研究基础与可行性修改稿/写作要点。
- 必要的成果—模块关联表：成果及状态、申请人贡献、支撑环节、可复用条件、证据位置。
- 影响项目的条件缺口与可行处理建议。
- 任务需要时的经费说明及其可追溯计算口径。
- 原始材料不足之处的准确边界，不制造“已核实”状态。

不会生成或冒充签署合作承诺、伦理许可、平台证明或预算审批；也不把申请人的合理未完成部分包装成已经实现的业绩。
