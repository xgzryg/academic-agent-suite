# 立项依据与研究价值

先读[共享规则](../../references/shared-rules.md)与[当前要求](../../references/current-requirements.md)。本分支处理“为什么开展这项研究”以及证据如何支持项目切入点。

## 输入和任务分流

读取当前题目、摘要/科学内容、选定科学问题、前期基础、有关文献、用户现有稿和官方模板。用户仅给一段时直接处理该段，注明可核查的范围。

- **已有稿修改**：定位论点、引用、冗余与逻辑缺口，在授权范围内重写。
- **只有方向或提纲**：先给论证结构、文献证据和段落要点。若目标机构允许相应AI起草且用户要求，可据已核实材料形成工作初稿。
- **只要求评审**：输出位置明确的诊断与修改建议，不擅自改稿。
- **适用2026国自然**：以构思、证据整理、结构论证及用户稿修改为交付；不能把AI直接生成的整份申请书标成作者稿或可提交稿。

## 执行步骤

1. **确定立项论证的终点。** 用一句话复述本项目要回答的问题及拟用的切入点；与用户题目、摘要、研究内容核对。若现有问题过宽，指出要收缩的对象、条件或结局。
2. **建立必要背景。** 选择能说明具体科学困难或现实需求的证据，避免大范围政策和流行病学铺陈。涉及数据、政策或现状时核对时间与适用人群；指南没有要求的宏观政策不强行添加。
3. **组织研究现状。** 经[文献与证据](../evidence-research/SKILL.md)核查原始研究与必要综述，按科学争议、解释或方法差异组织，而不是逐篇罗列。对每条重要研究线说明已解决什么、适用条件、局限及仍未解决的问题。
4. **推导缺口。** 缺口必须从已读证据得出，区分“尚未研究”“研究不足”“证据不一致”和“现有方法无法回答”。不能把缺少检索结果当成已确认空白。
5. **连接本项目。** 说明申请人哪些真实基础使该切入点可行，以及计划如何填补该缺口。把前期结果、由文献推得的假说和未来研究内容分开。
6. **安排段落。** 一段集中完成一个任务：提出判断、给出支持、说明限制或未决问题、衔接下一论点。可用“背景—现状—项目引出”组织，但一级标题、字数和页数由当前模板决定。
7. **同步引用。** 事实主张形成时记录支持它的来源与位置。保留必要经典文献和最新直接证据，不按期刊分区替代证据质量；并非每个过渡句都必须配引用。缺证主张需要查证、收缩或标待补，不事后硬配。
8. **修改并核查。** 检查每段是否服务中心问题，论证是否与研究方案相符，关键术语是否一致，结论强度是否超过证据。压缩重复背景和空泛价值句；已被支持的明确结论不机械改为含糊语气。

## 输出与交接

依据用户需要提供：

- 论证提纲或当前稿修订，保持清楚的章节与段落关系。
- 关键主张的简明证据表：主张、来源/位置、支持程度、拟用段落、未决事项。
- 引文身份及主张匹配的待查项，保留原引用供作者定位。
- 对研究方案提出的必要衔接修改，交给[研究计划](../grant-research-plan/SKILL.md)；需要文档编辑或导出时使用[学术文档](../academic-documents/SKILL.md)。

## 核查重点与边界

- 2026国自然面上与青年科学基金C类的三部分正文结构只适用于相应项目；“背景/现状/科学问题”可作为立项依据内部逻辑，不宣称所有基金必须采用同一提纲。
- 不照搬固定500/1000/500字、总4000字等示例限额；先读取实际要求，再决定篇幅。
- 不虚构国内外研究、引用、申请人发现或“国际首创”；“目前没有研究”的表述需要明确检索范围。
- 不把计划内容提前写成已证明的结果，也不以有前期研究为由掩盖剩余科学问题。
- 作者核实、适用的AI声明与依托单位要求是实际工作要求，不能用文末免责声明代替。
