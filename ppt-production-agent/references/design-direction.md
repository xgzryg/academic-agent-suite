# PPT 设计方向与视觉主控

用于整套演示的视觉规划、已有演示美化、模板适配和真实输出终审。它提供设计判断，不另建与主agent竞争的角色，也不要求安装外部设计服务。

## 复用已知方向

先读取用户当前PPT、模板、机构/品牌要求、已有配色与字体以及实际内容。确认这是新建、局部修正、模板适配、整体重设计还是参考学习；请求修一页时不扩大成整套重设计。

用户已有明确样式或项目已有稳定设计时，直接沿用。没有模板且视觉偏好不影响事实或目标时，选择适合场景的中性方向并继续；只有未决选择会实质改变整体布局、受众表达或范围时才补问。用户明确要求先访谈/看样张时遵守其确认步骤，已有答案不因换制作工具再问一遍。

## 一套演示只有一个视觉主控

本套PPT由一个已选方向决定字体角色、色彩含义、网格、空间节奏、图表标签和强调方式。其他技能补充图种、证据处理、编辑或实现方法，不各自建立一套风格。

解决冲突时依次考虑：

1. 用户明确要求、科学或业务含义、机构硬性规定与可读性。
2. 用户确认的模板、既有人工样式和真实输出条件。
3. 本次统一的设计方向。
4. 辅助视觉参考和后续微调。

参考模板可贡献布局、字体层级、色彩角色和留白习惯，不自动贡献其中的机构身份、示例研究或数据。对用户授权模板的修改在工作副本实施；局部美化保留其已确定内容和顺序。

## 让内容决定构图

先指出本页观众应理解的主张、关系或任务，再选视觉结构：

| 内容关系 | 合适结构 | 设计时要守住的条件 |
|---|---|---|
| 一项发现与支持证据 | 主要证据区 + 简洁判断/说明 | 证据图占足够面积，说明不能夸大结果 |
| 两种方案或旧/新变化 | 对齐比较、差异标注 | 指标、尺度、单位与比较条件一致 |
| 方法或决策流程 | 有方向的步骤/分支 | 节点关系清楚，条件不能被装饰箭头省略 |
| 多阶段进展 | 时间线或阶段表 | 时间、状态和任务依赖真实 |
| 知识教学 | 概念—解释—例子，或分步推导 | 深度符合受众；必要解释留在页面或讲稿 |
| 大量原始图表 | 主图放大、面板拆页、备用页 | 保留图号、图例、比例尺和论证所需上下文 |

不要把所有页面排成同样的卡片网格；封面、证据页、比较页、讲解页和收束页应随内容产生节奏。变化来自信息任务，不来自随意更换字体、渐变或装饰图。

## 字体、对比与密度

通过文字大小、字重、留白、对齐和位置建立清楚层级。标题与主体文字应有可感知差异，同层元素跨页一致；不要仅靠更多边框、阴影和圆角制造层次。

字号根据投影、电脑阅读或打印用途决定。密集内容先选择拆页、分步、精简次要信息或移入备注，再考虑缩小字号。教学页面可以保留适量完整解释，不能把“视觉简洁”理解成只留下无法独立理解的关键词。

保证文字和关键图形有足够明暗对比。颜色首先承担分组、状态或强调含义；同一含义跨页保持一致。类别或状态同时使用标签、形状或线型，避免只靠难分辨的颜色。科研数据、影像和统计图不能为了统一色调改变真实含义。

复杂图形可以保留为清楚标识的图片；原生文字、形状、表格或图表的编辑能力据实际实现说明。给整页截图加一个文本框不等于整页已经可编辑。

## 动效与多格式

先稳定信息、布局和可读性。只有用户要求，或分步揭示能明确帮助理解时才规划动画/转场；不得用动态效果掩盖结构不清。是否保留/支持原动画、旁白或自动播放以实际工具与测试结果为准。

PPTX放映、PDF阅读、讲稿HTML和打印讲义可能有不同展示需要。按用户真正要求的格式输出，保证内容一致；HTML交互只在实现后宣称，不把网页动效工具当PowerPoint动画能力。

## 以实际输出终审

生成后查看真实PPTX渲染，确认：观众的阅读顺序是否符合主线；重要信息是否足够突出；图像是否等比且图文对应；文字是否溢出、截断或被遮挡；图表标签是否可辨；不同页面是否保持一致的视觉语言。

针对真实问题修正，并在受影响页面核对结果。源代码、SVG预览或主题颜色一致都不能替代最终PPTX的实际显示检查。画面已经清楚且满足目标时直接交付，不为了追求“更有设计感”反复增加效果。
