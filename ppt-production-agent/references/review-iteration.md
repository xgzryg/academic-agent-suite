# 按需审查—修改循环

仅当用户要求多轮审改时读取。自动完成一次制作包括必要自检；不因此自动启动多个角色反复审稿。

## 开始与角色

复用当前文件、材料、人工固定项和授权。记录用户指定的最大修订轮数、目标、是否逐轮确认和核查重点；未给轮数的普通演示任务可说明采用最多 2 轮，若用户明确要求先设置则等待。目标用可观察行为描述，例如“5 页、讲稿与备注完全对应、数字与原表一致、实际渲染无截断、计划总时长 4 分钟”。时长估计不等于真人试讲。

支持真实委派且已获相应授权时，由不同子 agent 承担审查与修改。主控负责当前版本、目标和最终核对，不能把一个模型在同一回答里扮演两人称为独立子 agent。没有委派能力时说明可执行单 agent 分阶段审改；用户只接受独立评审时该条件缺失须报告。

## 一轮如何推进

1. 审查者读取最新 PPTX、真实来源、实际渲染与同步讲稿，只写问题清单，不改主文件。
2. 主控将实质问题、允许修改范围和当前工作稿交给修订者。修订者修改授权工作稿，保持数字、来源、证据状态与人工固定项；确需补充材料时列待补，不编造。
3. 修改后同步备注、讲稿、提示卡、目录和页序；重新导出受影响载体。生成器或导出失败时不能作为成功轮次继续。
4. 审查者或主控回读最新结果检查完成目标，记录已解决和仍未解决事项。只有仍有实质问题且未达上限时进入下一轮。

每个角色使用任务目录下各自的反馈文件；同一时刻只有一个执行者写主 PPTX。复用当前版本记录，避免并行者拿旧故事板覆盖最新人工编辑。

## 可直接交给子 agent 的任务

**审查者**：读取这些当前文件与真实材料：[路径]。按已定目标：[目标]，核查事实、图文对应、显示、备注/讲稿和时长。仅输出带页面 ID、依据、严重程度和修法的实质问题；正确可明确通过；不要修改演示文件，不凑问题或评分。

**修订者**：读取当前工作稿：[路径]，依据问题文件：[路径]，在范围：[范围] 内修复。保持这些固定项：[项目]。使用现有主生成路径，同步受影响的 PPTX、备注与讲稿，记录实际完成和待补；缺失证据不能猜测。不得发布、发送、安装或修改本任务外文件。

**回查者**：比较本轮问题与当前实际输出，确认问题是否已解决及是否引入新的相关错误。仅重新检查受改动影响的内容。报告目标达成、仍需修改或受阻，并给依据。

## 结束条件

- 达到目标：说明完成，给当前文件。
- 达到最大轮数：如实说明尚存问题，不能写成“已达标”。
- 必需材料、授权或工具缺失：停下依赖部分，交付当前可用结果和明确待补项。
- 用户要求停止：保存当前可用稿并停止。

循环在当前获授权会话中执行，不自行注册定时任务、后台服务或外部模型账户。需要后台定时执行时由用户另外明确要求，再使用宿主实际自动化能力。
