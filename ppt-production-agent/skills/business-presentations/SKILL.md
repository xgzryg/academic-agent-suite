# 商业、项目与通用工作演示

沿用主入口的事实、生成、模板、授权和交付规则。此分支负责内容组织，不另选整套 PPT 引擎，不根据参考材料中的账户/联系人自动发送或发布。

## 识别演示目的

用用户当前目的选择结构，不把所有业务汇报做成融资路演：

| 用途 | 推荐叙事 |
| --- | --- |
| 工作总结/项目进展 | 目标 → 已完成证据 → 关键差异 → 原因 → 当前问题 → 下一步及需要支持 |
| 产品/技术介绍 | 用户问题 → 使用场景 → 方案与流程 → 真实演示/证据 → 使用条件 → 下一步 |
| 管理决策/方案比选 | 待决问题 → 约束 → 可比较选项 → 代价与收益 → 风险 → 建议及需要的决定 |
| 销售/合作介绍 | 对方需求 → 对应价值 → 真实案例/能力 → 合作范围 → 交付安排 → 明确行动 |
| 创业/融资/项目申请 | 问题与机会 → 产品方案 → 实际验证 → 执行计划 → 资源与风险 → 明确申请 |
| 科普/公众技术交流 | 可理解的问题 → 必需背景 → 具体解释/例子 → 证据与边界 → 可采取的下一步 |

用户有既定结构或模板时优先采用。金融投资建议、法律或医疗实质结论仍按实际任务核查，本分支不把通用演示框架冒充专业意见。

## 内容准备

1. 提取受众要做什么决定、目前知道什么、时长与可公开范围。已给清楚的信息不重复询问。
2. 分类真实结果、阶段目标、预测、估计、假设、演示示例。市场规模、营收、客户评价、节省成本和融资承诺没有来源时不得补造。
3. 先写一段中心信息，再做逐页故事板。每页一个明确作用：背景、证据、比较、流程、路线图、决策或行动。图表使用真实数据和准确单位，不用装饰性比例图暗示不存在的量化结果。
4. 引用用户指定品牌、模板或示例的视觉结构；清除示例旧姓名、机构、日期、占位字与不相干研究。未提供商标或联系方式时不虚构。
5. 项目进度区分已完成、进行中和拟开展。时间线有日期/时间依据；未知资源和审批写待落实，不自动填“已获批准”。
6. 与 `../speech-writing/SKILL.md` 配合写清楚可说的讲稿，屏幕避免长段落。商业短讲优先让受众看到事实和请求，详细技术放备用页。

## 交付检查

核对对比口径、时间单位、货币和分母，计划与实际是否混淆，建议是否超出材料，行动请求是否明确。从最终页而非旧大纲导出讲稿；内容修订同步 PPT notes/HTML/Word。审查与排练调用 `../qa-rehearsal/SKILL.md`。

只交付用户要求的文件，制作不自动授权发送客户、上传公开仓库或购买素材/服务。示例数据需明确“合成演示”，不以本分支模板文字冒充真实客户证言。
