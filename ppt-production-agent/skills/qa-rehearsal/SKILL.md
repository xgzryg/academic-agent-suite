# 演讲检查、排练与问答

读取 `../../references/speech-format.md`。先确定任务是一次审查、按意见修稿、准备问答、互动排练，还是明确要求的多轮审改；不要把普通自检扩展成无限循环。

## 审查

- 内容：每页有清楚消息、关键事实有来源，标题结论与证据相符。区分用户结果、论文作者解释、推断、计划和教学示例。
- 图表：核对实际源图/数据，轴、单位、图例、分组、样本量、不确定性与页上解释对应；复杂图需要足够讲述时间。
- 载体：核对当前页序、标题、备注、提示卡、来源和导出文件。PPTX 结构检查无法独自证明实际渲染无溢出；调用包内制品/导出检查分支，说明真正检查过的范围。
- 听众：听众能否理解必要术语、前置概念和图的读法；文字大小、对比度、字幕与图例适合展示场景。
- 时间：内容、互动、演示和问答相加是否落在当前时段；复杂图/公式不能照统一“每页一分钟”分配。

每项实质问题指出页面 ID、当前位置、依据和具体修法。正确处可直接说正确，不凑问题数。审查者只给问题和修订建议；由当前主制品生成器修改，避免互相覆盖。视觉润色不擅自改变结论、数字、作者、引用或顺序。

## 问答与备用页

只围绕当前内容实际可能被问到的理解、方法、对照、结果、局限、创新与应用准备问题。每问给简短口语回答、支持来源/页面、必要的备用页。没有证据时明确“目前未验证/原文未说明”，可提建议，不写成已经做过的试验。商业问题可覆盖客户、成本、资源、风险和决策；病例问题区分事实、临床解释和教学讨论，不做无根据的诊疗结论。

## 排练

输出可执行的分段练习建议、难讲页面、开场/结尾、自然转场和简版路线。已有录音/试讲计时优先；只有文字时提供估计，不能声称真人实测完成。独立 HTML 可本地计时，但不会记录演讲声音、自动评分或向外发送。

互动排练仅在用户明确要求时开启：按用户节奏提一个实际相关问题或让其讲一段，再给可核对反馈。用户回答前不模拟“已得到回答”。

用户明确要求循环时，记录最大修订轮数与完成目标；每轮检查最新制品，修订后再核受影响页。若使用真实子 agent，说明实际角色与能力；不支持时报告单 agent 检查，不伪装为多人独立评审。达到目标、轮数上限、用户停止或必需资料缺失时分别记录，不把“到上限”说成“已达标”。

需要循环的具体角色分工、交接提示词和停止规则时读取[审查—修改循环](../../references/review-iteration.md)。

## 常用工具

```text
python scripts/speaker_pack.py storyboard.json --pptx current.pptx --check-only
python scripts/speaker_pack.py current.pptx --out-dir <rehearsal-output> --zh-cpm 220 --en-wpm 125
```

同步检查只覆盖页数、顺序、ID、标题和实际备注；数字/图表/引用科学核查由 agent 阅读事实源完成。估计语速可调，并说明互动和问答是否另计。

交付简短审查结果、已改内容、实际稿件和未解决问题；修订引起的 PPT/讲稿/HTML 变化在授权范围内同步。
